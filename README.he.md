# בודק תיק עסקה · BuildLab

כלי שמקבל את מסמכי עסקת מכר דירה (נסח טאבו, הסכם מכר, מכתב כוונות מהבנק, דו"ח רשם המשכונות), גם סרוקים,
ומסמן כל סתירה ביניהם – עם ציטוט מהמסמך לכל ממצא.

## איך זה עובד

1. **קריאה** (`lib/extract.ts`) – כל PDF נשלח ל-Claude, שמחזיר את סוג המסמך, תמליל מלא, ונתונים מובנים (בעלים, ת.ז., משכנתאות, הערות, עיקולים, תשלומים...) עם ציטוט לכל פרט. סריקות נקראות דרך הראייה של Claude.
2. **הצלבה** (`lib/rules.ts`) – כללים קבועים בקוד משווים בין המסמכים: בעלים מול מוכרים, ת.ז., גוש/חלקה, שטח, הצמדות, בנק משעבד, הערות אזהרה, עיקולים, משכונות, יתרת סילוק מול התשלום לבנק, תוקף מכתב הבנק, סכום התשלומים, עדכניות הנסח, חכירה מרמ"י, ירושה. אותם מסמכים → תמיד אותם ממצאים.
3. **סקירה נוספת** (`lib/review.ts`) – Claude עובר על התיק כולו ומחפש בעיות שהכללים לא מכסים. ממצא כזה נשאר רק אם הציטוט שלו באמת נמצא במסמך.
4. **אימות ציטוטים** (`lib/verify.ts`) – כל ציטוט נבדק מול הטקסט של ה-PDF עצמו (או מול התמליל, בסריקה). ציטוט שלא נמצא מסומן "לבדיקה ידנית".

המסמכים מעובדים בזיכרון בלבד ולא נשמרים.

## הרצה מקומית

```bash
npm install
cp .env.example .env.local      # ולהדביק את מפתח ה-API מ-console.anthropic.com
npm run test:rules              # בדיקת הכללים על 6 התיקים – בלי API, בחינם
npm run eval                    # הרצה אמיתית על 6 התיקים + ציון מול דפי התשובות
npm run dev                     # האתר: http://localhost:3000
```

`npm run eval` מדפיס לכל תיק כמה ממצאים נמצאו מתוך הצפויים, מה פוספס ומה הומצא, ושומר את הכל ב-`eval-results/`.
אפשרויות: `npm run eval -- case01 case05` (רק חלק מהתיקים), `npm run eval -- --no-review` (בלי הסקירה הנוספת).

## תיקי הבדיקה

`cases/case01` … `case06` – תיקים בדויים עם `answer_key.md` / `answer_key.json`:

| תיק | מה הוא בודק | ממצאים צפויים |
|---|---|---|
| case01 | נהריה – עסקה עם הרבה בעיות | 11 |
| case02 | חיפה – עסקה נקייה (כל ממצא = המצאה) | 0 |
| case03 | קריית מוצקין – מכירה של יורשים | 3 |
| case04 | כרמיאל – חכירה מרמ"י ועיקול | 4 |
| case05 | קריית ביאליק – פערים עדינים + מלכודת | 2 |
| case06 | עכו – כל המסמכים סרוקים | 2 |

`case01/01b_nesach_tabu_scanned.pdf` הוא עותק סרוק של הנסח, לבדיקה ידנית של OCR (ה-eval מדלג עליו).

## העלאה ל-Vercel

1. להעלות את התיקייה לריפו ב-GitHub ולחבר ל-Vercel.
2. ב-Vercel → Settings → Environment Variables: `ANTHROPIC_API_KEY`.
3. הבדיקה רצה עד 120 שניות (`maxDuration` ב-`app/api/check/route.ts`) – בתוכנית Hobby המקסימום נמוך יותר; אם יש timeout, להוריד ל-60 או לשדרג.

## מודל ועלות

ברירת המחדל: `claude-sonnet-5-5` (אפשר לשנות עם `DEAL_CHECKER_MODEL`). הערכה גסה: כמה עשרות אגורות עד דולר לתיק, תלוי במספר העמודים – כדאי לבדוק בקונסול אחרי ה-eval הראשון.

## מגבלות ידועות

- נבדק רק על תיקים בדויים. הצעד הבא הוא פיילוט על תיקים אמיתיים (אחרי השחרת פרטים מזהים).
- הכלי מסייע לעורך הדין ואינו מחליף את הבדיקה ושיקול הדעת שלו.
